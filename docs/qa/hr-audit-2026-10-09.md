# HR legacy pages audit — 2026-10-09

Scope: payroll (records, batches), reimbursements, deductions, salary profiles, promotions, employee assets,
attendance, leave approvals, sales commissions. Method: API audit + live race scripts + built-in browser + pytest.

## Findings fixed
| Area | Finding | Fix |
|---|---|---|
| All HR GETs | One permission guarded every resource | Per-resource view permissions |
| Inputs | Loose schemas: negative/huge amounts, unbounded text, int4 ids, no enums | Strict `hr/inputs.py`, limit cap 5000 |
| Payroll | Manual records accepted client totals; edits after batching; future/ancient periods; leavers/not-in-service paid; EPF/ETF for casual; unpaid leave ignored; approver = generator | Server-computed totals, locked once batched, period window, pro-rating, no-pay deduction, maker-checker |
| Reimbursements | No branch scope; self-approval; approved > claim; partial pay; verifier = approver; approval left open on delete | All enforced |
| Deductions | Any employee id; editable after payroll | In-service check; locked once payroll exists |
| Salary profile / promotion / asset | Duplicates, wrong holder, designation not synced | Immutable profile, duplicate guard, one asset holder, status sync |
| Attendance / leave | Duplicate check-ins (3 of 8 succeeded), 8 identical leaves, balance overdrawn, client-supplied minutes | Advisory locks, server-computed minutes, branch scope |
| Attendance status | Checked-in-not-out shown "absent" | Now "present" |
| Attendance page | Crash `Invalid time value` on any row | `fmtTime` |
| Sales commissions | Unbounded ranges, approver = finalizer/claimant, pay without approval or a paid batch | Strict ranges, row locks, rules enforced |
| Frontend | "" sent for empty dates (422); free-text employee/asset ids | "" -> null interceptor; pickers on Deductions and Assets |

Live race audit (after fixes): salary profile x8, manual payroll x6, promotion x6, same-day leave x8, reimbursement approve x8 / pay x6,
payroll run x6, check-in x8 -> exactly 1 winner each; approve-vs-reject -> 1 winner.
