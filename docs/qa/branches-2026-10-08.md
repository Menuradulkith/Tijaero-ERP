## Suggested fixes (not applied)
1. Pydantic: `branch_name`/`branch_code` → `constr(strip_whitespace=True, min_length=1, max_length=255)`; `email` max 75; `contact_number` max 255; `address` max e.g. 1000; reject `active=None` on update. Frontend: trim before `isFormValid`, add `maxLength`.
2. Case-insensitive uniqueness: compare `lower(trim(...))` in service + unique functional indexes (migration) for name, code and email.
3. Constrain path ids (`Path(..., ge=1, le=2147483647)`).
4. `TPhoneField`: don't map a bare dial code to `""` while focused (or keep the dial code in local state).

## Fix log (2026-10-08)
All six findings fixed, plus the requested Address redesign. Verified with 41 new backend tests (`backend/tests/test_branches_validation.py`, 50 passing together with the auth/logout/user tests) and in the browser.

- **#1 blank name/code:** `BranchCreate`/`BranchUpdate` use `strip_whitespace + min_length=1` (`backend/app/modules/branches/schemas.py`); null `branch_name`/`active` on update → 422. UI `isFormValid` and the location guard trim.
- **#2 over-length → 500:** `max_length` on name/code (255), email (75), address parts (255/120/120/20), legacy address (1000) → 422. UI inputs have matching `maxLength`.
- **#3 case/space duplicates:** repository lookups compare `lower(trim(...))`; email stored lower-case; `check-code/name/email` are case-insensitive. Service-level only: **no DB functional unique index** because the dev DB already holds case-variant QA rows and other environments may too; recommend adding one after a data clean-up.
- **#4 5xx on odd input:** path/query ids bounded to int4 (`BranchId`, `ExcludeId`) → 422; null/blank handled by the schema.
- **#5 `TPhoneField`:** keeps the library's raw text in local state (a bare `+94` is no longer fed back as `""`), resets a fully emptied field to the default dial code, and drops a trunk `0` after `+94` so `0771234567` ≡ `771234567`. Verified fresh field, after-clear typing, edit and blur-validation. Also fixes the same behavior on the Customers/Suppliers forms.
- **#6 address length:** see #2.
- **Address section (supplier-style):** new columns `address_line1/2, city, state, postal_code` (migration `s81_branch_structured_address`, existing `address` text copied into line 1; legacy `address` kept in sync on save and still accepted from older clients). The page now has a separate **Address** card — Address Line 1/2, City, State / Province, Postal Code — matching the Supplier page (single address, so no billing/shipping split and no Country selector).

Verified end to end in the UI: created a branch with code `qa-ui-…`, name with surrounding spaces, `QA.UI…@Example.com`, phone `0771234567` and a full address → stored once as `QA-UI-…`, trimmed name, lower-case email, `+94771234567`, composed legacy address `12 Galle Road, Level 2, Colombo, Western, 00300`. Migrated address of the real branch shows in Address Line 1 (read-only in view mode). Test branches were deactivated.

Notes (a) and (b) below were fixed in a follow-up (see "Follow-up fixes"); (c) stands.

- (a) POST/PUT to `/branches` (no trailing slash) was answered with a 307 redirect, so every list load and write was sent twice.
- (b) The list endpoint's `total` ignored `active_only`, so pagination counts were wrong when that filter was used.
- (c) The wider backend suite has 22 failures in unrelated modules (sales guardrails, procurement, people, inventory, supplier integrity; plus a `ProductPriceTier` import error in `test_accounting_gl_reliability`); none involve branches, but they were not compared against a clean checkout.

## Follow-up fixes
- **(a) 307 redirect:** `branchApi.getAll` and `create` now call `/branches/` (the backend route). Verified: page load = one `GET /branches/ 200`; create = one `POST /branches/ 201`, no redirect. Same fix benefits Attendance and Users pages that call `branchApi.getAll`. Other modules were not audited — the same slash-less pattern may exist elsewhere (look for `apiClient.get|post("/<module>")` without a trailing slash, or enable a backend-wide fix).
- **(b) List total:** `BranchRepository.count()` / `BranchService.get_total_count()` take `active_only` and the list endpoint passes it. Verified live (all 24/24, active 2/2) and by `test_list_total_respects_active_only` / `test_list_pages_count_matches_filtered_total`.
- **Heads-up (not fixed):** `BranchesPage` loads branches with `getAll(1, 100)`, so it would silently show only the first 100 once there are more than 100 branches.
