# Login / Auth – UI + API evaluation (2026-10-08)

Scope: `/login` (Password + Passcode tabs), route protection, session persistence, logout, rate limiting, mobile width. Local dev, `admin` seed account. Source: `frontend/src/auth/pages/LoginPage.tsx`, `frontend/src/state/authStore.ts`.

## Passed
| Check | Result |
|---|---|
| Unauthenticated deep link (`/sales/orders`) | Redirects to `/login`; after valid login returns to `/sales/orders` |
| Empty / username-only / whitespace password | Toast "Username and password are required", no API call |
| Wrong password and unknown user | Same toast "Invalid credentials" (no user enumeration), 401 only |
| SQL-ish input (`' OR 1=1 --`) | Rejected as normal bad credentials |
| Passcode tab | 6 PIN cells, submit disabled until complete, auto-submits on 6th digit, invalid → "Invalid username or passcode.", PIN cleared |
| Session persistence | Survives reload; `auth-storage` holds token + user |
| Logout (avatar → Logout) | Clears auth state, lands on `/login`, Back button stays on `/login` |
| Brute-force protection | 4th rapid bad login → HTTP 429 |
| Mobile 390x844 | No horizontal overflow, card readable |

## Findings
| # | Severity | Finding | Repro / evidence |
|---|---|---|---|
| 1 | Medium — **FIXED 2026-10-08** | Logout did not revoke the access token. `POST /auth/logout` returns 200 but the same bearer token still gets 200 on `GET /users/me`. A stolen token stays valid until `exp`. | Login via API, call `/auth/logout`, replay token on `/users/me` |
| 2 | ~~Low~~ Retracted | `pwd` claim is a truncated SHA-256 of the stored hash (`get_password_marker`), non-reversible and used deliberately to invalidate tokens on password change. Not an issue. | `backend/app/core/security.py` |
| 3 | Low | Access token and full user object (~33 KB, incl. permissions) are persisted in `localStorage` (`auth-storage`), exposed to any XSS. A secure cookie is also set by the backend. | `localStorage['auth-storage']` |
| 4 | Low — **FIXED** | Signed-in users can still open `/login` (no redirect to dashboard). | While authenticated, visit `/login` |
| 5 | Low (a11y) — **FIXED** | Show/hide-password `IconButton` has no `aria-label`; tap target 36x36 (<44px). | `#login-panel-password form button[type=button]` |
| 6 | Low (a11y) | `getByLabel('Password')` is ambiguous because the tabpanel is `aria-labelledby` the "Password" tab; harmless to users, breaks label-based test selectors. | Playwright strict-mode violation |
| 7 | Info — **FIXED** | On mobile the Sign In button measures ~31px high although the source asks for `size="large"`, `py: 1.5` (theme override likely wins). Tap target below 44px. | `getBoundingClientRect` at 390 wide |
| 8 | ~~Info~~ Retracted | Toasts (`react-hot-toast`) render `role="status"` `aria-live="polite"`, verified in the DOM, so screen readers do announce them. | DOM check |

Not tested: forced password change flow (`must_change_password`), passcode lock-out/expiry banners, idle-session timeout (`IdleSessionManager`), token refresh on 401, dark mode on login.

## Fix log
- **#1 logout revocation:** access tokens now carry a `jti`; `POST /auth/logout` denylists the access + refresh token `jti`s in new table `auth_revoked_token` (migration `s80_auth_revoked_token`); `get_current_user`, `get_current_user_flexible` and `/auth/refresh` reject revoked tokens. Other sessions of the same user are unaffected. Tokens issued before this change have no `jti` and stay valid until they expire. Tests: `backend/tests/test_logout_revocation.py`. Verified live: replayed token → 401 after logout, second session → 200, refresh after logout → 401.
- **#4:** `LoginPage` now renders `<Navigate to={from}>` when already authenticated (gated on `user` being loaded and no login mutation in flight, so the two-step `login()` in `onSuccess` is not pre-empted). Honors `?redirect=`. Verified: signed-in `/login` → `/dashboard`; `/login?redirect=/sales/customers` → `/sales/customers`.
- **#5:** show/hide button has `aria-label` ("Show password"/"Hide password") and `aria-pressed`, padding raised so it measures 48x48.
- **#7:** both Sign In buttons get `minHeight: 48` (theme's `<600px` padding rule was overriding `py`). Measured 262x48 / 328x48 at 390px wide.
- **Open by design:** #3 (token + user in `localStorage`) needs an architectural change (in-memory access token + httpOnly refresh cookie only) — not done. #6 only affects test selectors.
- **#1 follow-up (race):** `revoke()` used check-then-insert, so two simultaneous logouts of one token could hit the `jti` primary key and 500. It is now a single atomic `INSERT … ON CONFLICT DO NOTHING` (`backend/app/auth/token_revocation.py`). Verified live: 3 rounds × 25 parallel logouts of the same token → 75/75 HTTP 200, token rejected afterwards (401). Tests added: `test_revoking_same_token_twice_is_a_noop`, `test_double_logout_of_same_token_succeeds`. (A savepoint + `IntegrityError` catch was tried first; it failed under SQLAlchemy's savepoint handling, so it was dropped.)
