# Finance module QA: 2026-10-24

Environment: local dev (frontend :3000, backend :8020, Postgres `erp_postgres2` :5435). User: `admin` (superuser).
Method: Playwright sweep of all 33 finance routes, live API checks of the GL, TB, IS, BS, day-end and posting failures, direct DB queries, and a code audit of `backend/app/modules/finance/*` against standard double-entry rules.

**Verdict: the finance module is not yet ERP-grade accurate.** The UI pages load cleanly, and every journal entry in the GL balances (Dr = Cr per JE, 1,418 lines). But:
- the statements are wrong by construction in several places;
- 535 source documents never reached the GL;
- the cashbook is empty;
- three QA rows of 10^30 make every statement unreadable.

### GL-driven cashbook (follow-up, same day)
- **Writer:** the cashbook is now written **only** from GL cash/bank/cheque postings (1010/1020/1040), one row per journal entry, by `record_cashbook_from_gl`. It is called from the GL gateway, from manual JE posting and from reversals.
  - Rows keep the page's entry types (`invoice_receipt`, `customer_credit_settle`, `voucher_sale`, `customer_advance`, `supplier_payment`, `expense`, `bank_deposit`) and legacy source tables, and add new types (`grn_payment`, `sale_return_refund`, `purchase_return`, `payroll`, `journal_entry`, …).
  - The party name is resolved from the source document (customer, supplier, vendor, employee).
  - The payment method comes from the account (Cash / Bank Transfer / Cheque), with Card detected from the line description.
  - A bank deposit is recorded as money leaving the till, as the day-end identity expects.
- **Retired:** migration `s104` drops the nine insert-time `trg_cashbook_*` triggers. The four Python cashbook inserts (purchase return, verified supplier payment, supplier advance return, sale return refund) are removed. The cashbook page's "supplier payment must be verified" filter is no longer needed and is removed.
- **Rebuilt:** `scripts/rebuild_cashbook_from_gl.py --apply` rebuilt the cashbook from the GL: 320 rows, with running balances recomputed per branch. It skips the voided 1e30 QA pair (out of NUMERIC(15,2) range; it nets to zero on 2026-10-12).
- **Day-end:** all 7 October days with activity reconcile at **0.00** (10-11, 10-12, 10-13, 10-21, 10-22, 10-23, 10-30). On the cashbook page, October shows 320 records, with totals in 21,998,530,514.49 net, which plus the 1,440 of deposits equals GL cash + bank + cheques.
- **UI:** rows are keyed by the cashbook row id; the old source-table + source-id key could repeat, for example a GRN and its cancellation. The page has labels for the new entry types.
- **Tests:** 3 new cashbook tests; the 3 new finance files pass 70/70. The cashbook-related suites pass: GL reliability, concurrency, lot transfers, the purchasing, sales and finance QA fixes, and the sales audit (138 tests). `test_money_audit_cross_module_2026_10_12.py` still fails 16 absolute-ledger assertions that expect an empty database. Its cashbook = GL checks now hold.
