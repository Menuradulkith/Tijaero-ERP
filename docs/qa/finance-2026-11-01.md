# Finance module QA — 2026-11-01 (after the Sri Lanka simplification)

Scope: the whole finance module after phases A–E and the clean-up of features that
don't fit Sri Lankan SMEs. Run against the local dev stack (frontend :3000, backend :8020)
with QA-prefixed data. Tools: Playwright MCP for the UI, an API script for the money
flows (`finance_e2e.py`, kept in the session scratchpad) and DB checks for the ledger.

## Removed before testing (don't fit / add needless complexity)

| Removed | Why | What remains |
|---|---|---|
| Posting rules split by tax code | One VAT regime in Sri Lanka | One output-VAT (2210) and one input-VAT (1140) account |
| "Account needs a cost center" rule | Extra setup few SMEs use | Cost centers with a branch default |
| Renaming voucher types | Codes appear in JE numbers; should stay fixed | Read-only list |
| Payment Terms list (+ customer/supplier `payment_term_id`) | SL businesses use credit days, already on every form; the list had no UI to assign it | Credit sales still store a due date (invoice date + credit days) |
| Posting into a closed period by finance managers | Weakened "closed means closed"; reopening already covers it | Unchanged period rules |

Migration `s121_simplify_finance` drops the tables and columns.

## Cross-module pass: every flow that posts to finance (same day)

How: listed every source that writes journals (37 reference types across sales, purchasing,
customers, HR, inventory, manufacturing, finance); ran the cross-module money tests on a
**fresh, empty database** (migrate + seed) as well as the dev DB; added tests for the flows
nobody tested (petty cash, gift-voucher refund); scanned all posting code for documents that
post twice under one reference; walked petty cash end to end in the browser and checked the
ledger rows it wrote.
