## Suggested fixes (not applied)
1. **#1:** only allow assigning roles the caller already holds (or require a dedicated `users:assign_role`/superuser); block non-superusers from modifying superusers, from changing their **own** roles, and from setting passwords on higher-privileged users.
2. **#2:** frontend: send `undefined`/omit empty optional fields (or backend: coerce `""` → `None` for dates/optional strings).
3. **#3/#5/#6/#7:** same pattern as the Branches fix — `strip_whitespace + min_length=1` on required text, reject `null` for `is_active/is_staff`, case-insensitive uniqueness for username/email/employee ID (and a DB index once data is clean), validate that group/branch ids exist (and branches are active) → 422/400 with a correct message, bound path ids to int4.
4. **#4:** one shared password validator (min length + character classes, reject whitespace-only and username-equal) used by create **and** update **and** the change-password endpoint.
5. **#8:** sniff magic bytes (Pillow `Image.verify`), drop SVG from the allow-list or sanitize, serve uploads with `Content-Disposition`/`nosniff`, look up the user before saving the file.
6. **#9:** pass `active_only=true` for pickers/filters.

Not tested: load; forced-password-change screen; blocked-user (too many failed logins) flow end to end; passcode set/lockout; role CRUD page (`/roles`) — suggest its own pass given #1.

## Fix log (2026-10-08) — all 12 findings addressed
Verified by 95 new/updated backend tests (`tests/test_users_security.py`; 145 pass with the auth, logout, branch and user suites) and live in the browser/API. Full backend suite: 465 pass, the same 22 failures in unrelated modules as before (no regressions).

**#1 Privilege escalation** — new `backend/app/auth/user_access.py`, applied in `modules/users/api.py` to create, update, unblock, force-reset and profile-picture endpoints:
- A non-superuser may only grant roles whose permissions they already hold, may not change **their own** roles or branches, and may only assign branches they belong to.
- A non-superuser may not modify a superuser, nor a user who holds permissions they don't (editing includes password reset, which would hand over that user's access).
- Nobody can deactivate their own account; the last active superuser can't be deactivated.
- Replayed live: self-promotion to Admin, granting Admin to others, editing/resetting/deactivating the superuser and creating a user with the Admin role all return 403 (self-deactivate 400); `admin` unchanged and still logs in.
- **Trade-off to be aware of:** because of the "no more privileges than you" rule, a manager whose role is only `users:view`+`users:update` can **not** edit users who hold other permissions (e.g. Viewer). Only users whose permissions are covered by the caller's can be managed. Admin-group users (all permissions) are unaffected. If you want a broader "HR can manage staff" role, give it the permissions of the staff it manages or introduce an explicit delegated-admin permission.

**#2 Birthdate** — backend coerces `""` to "not set" for all optional fields (`birthdate`, `gender`, `middle_name`, `occupation`, `phone_number`, `date_joined`, `email`); the page also sends `null` instead of `""`. Verified: a user created from the UI with Birthdate blank.

**#3 Blank required values** — username/first/last name are trimmed, non-empty, length-capped; employee ID 3–255 chars `[A-Za-z0-9_-]` (the same rule the UI had); username may not contain whitespace or `/ \`.

**#4 Passwords** — one policy in `app/core/password_policy.py` (≥ 8, ≤ 72 bytes, upper, lower, digit, special, not blank, not equal to the username) used by create, update and the change-password schema. `""` on update still means "unchanged".

**#5 Duplicates** — username, email and employee-ID checks (create, update, `check-*` endpoints) compare `lower(trim())`; emails stored lower-case. Service-level only: **no DB unique index**, because case-variant QA rows already exist in this database; add functional unique indexes after a clean-up for race-proof enforcement.

**#6 References** — unknown role/branch ids → 400 with a precise message; inactive branches can't be newly assigned (a branch that went inactive after assignment can stay); duplicate ids collapsed.

**#7 5xx** — null/blank required fields → 422; user ids bounded to int4 on every route.

**#8 Uploads** — file signature must match the declared type (PNG/JPEG/WEBP/SVG); SVG with scripts, event handlers, `javascript:`/external `href`, `foreignObject`, entities is rejected (logos keep plain SVG); avatars are raster-only; the user is looked up **before** the file is written (no orphans); `/uploads` is served with `nosniff` and a sandboxing CSP.

**#9 Pickers** — `branchApi.getAll(..., activeOnly)`; Users page filter/pickers and HR Attendance now request active branches only (Add User branch picker went from 24 options to 1). Branches the selected user already holds stay visible.

**#10** — birthdate ≥ 1900 and date joined ≥ birthdate (create, update vs stored); gender is a fixed dropdown in the UI.

**#11** — `/users` and `/groups` calls use the trailing-slash routes (no more 307s); the form has `maxLength` on username (50), password (128), email (254), employee ID (255), names (30).

**#12** — empty state now says superusers aren't listed and how to add a user, or "No users match the current filters".
