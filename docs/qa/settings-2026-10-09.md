# Settings QA — 2026-10-09

Scope: `/settings` (Profile, Preferences, Notifications, Email Templates, Email Logs), `/company-settings` (Company Details, Payment Cards, Currency, Security) and their APIs (`/settings/*`, `/communication/email/*`).
Method: Playwright MCP unavailable → API audit with an async Python client + built-in browser smoke. Global settings were snapshotted and restored; see "Side effects of the test run" at the end.

## Findings

| # | Area | Finding | Severity | Repro |
|---|---|---|---|---|
| 1 | Security | **`PUT /settings/profile` returns the whole User row, including `hashed_password`**, plus `permissions`, `groups`, `is_superuser`, `verify`, `blocked`, `created_by` … (no response model). The same bcrypt hash is exposed to anything that can read the response (browser devtools, logs, a future XSS) | **Critical** | `PUT /settings/profile {}` → inspect JSON |
| 2 | Security | **Email templates and email logs have no permission check** (`get_current_active_user` only). Any logged-in user can read the last 100 sent emails (recipients, subjects, errors) and rewrite the templates used for every customer/supplier email — a phishing/persistence vector | High | `PUT /communication/email/templates/{id}` as a user with no email/settings permission |
| 3 | Validation | **Preferences accept anything and can brick the page**: `theme: null` / `items_per_page: null` store NULL and then `GET /settings/preferences` returns **500 for that user permanently** (the Settings → Preferences tab and anything reading prefs break); also accepted: `theme: "neon"`, `timezone: "Mars/Base"`, unknown `default_branch`, `items_per_page` 0 / -5 / 1 000 000 000, `date_format: "<b>"`. Over-long or huge values → 500 | High | `PUT /settings/preferences {"theme": null}` then GET |
| 4 | Validation | **Company settings accept garbage and 500 on size**: blank name / address / email, `company_email: "not-an-email"`, `<img onerror>` name, negative or >100 depreciation and tax rates, `NaN`, negative leaves (and 99 999), negative / 500 % card surcharges, `fiscal_year_start: "hello"` / "13-45", `default_currency: "XXX"` or `"lkr"` (not a configured currency — breaks every page that formats money), `company_logo_id: -1`. Over-long name (256), email (255), fax (13), tax reg no (51), fiscal (11), currency (4), `company_logo_id: 2^40`, leaves 2^40 → 500. Explicit `null` on required fields → 409 | High | `PUT /settings/company` |
| 5 | Validation | **Profile**: blank first name accepted; 256-char names, bogus gender, `birthdate: "2026-02-30"`, `date_joined: "nope"` → 500; future birthdate (2999) accepted; free text like `"yesterday"` is accepted and stored (Postgres date shorthand → birthdate silently became yesterday's date); `null` first name → 409 | High | `PUT /settings/profile` |
| 6 | Validation | **Currencies**: code accepts digits and symbols (`123`, `!@#`); blank name / blank symbol accepted, 101-char name or 11-char symbol → 500; update with blank name accepted, `null` → 409; ids 2^40 on PUT/DELETE → 500; deactivating the **active** currency succeeds (the company's default is then an inactive currency); 8 parallel creates of one code → 1×200 + 2×409 + 5×400 (clean enough, but 409 is the wrong code for a duplicate) | Medium | `POST /settings/currencies` |
| 7 | Validation | **Email templates**: blank subject / body accepted, subject 256 → 500, id 2^40 → 500, 1 MB body accepted; unknown/unbalanced placeholders (`{nonexistent}`, `{title`) accepted → a later send will fail or print raw braces | Medium | `PUT /communication/email/templates/{id}` |
| 8 | Validation | **Path ids unbounded** → 500: notifications `/{id}/read` and DELETE with 2^40, `GET /communication/email-draft/invoice/2^40`; `email-draft/bogus/1` returns 200 for an unknown document type | Medium | |
| 9 | IDOR / info | `GET /communication/email-draft/{type}/{id}` looks up any customer/supplier/document by id and returns its email address and names to any active user (no branch or permission check) | Medium | |
| 10 | Race | Company settings single-row writes and 8 parallel identical updates are fine (8×200). No optimistic-concurrency token on company settings: two admins saving different tabs overwrite each other (last write wins, fields not sent are kept) | Low | |
| 11 | UI | Company Details and Profile inputs have no `maxLength` (company name, address, tax no, names); Profile shows no validation for dates | Low | |
| 12 | Misc | Notification list `skip=2^40` returns 200; `limit=100000` allowed | Low | |

## What is OK
- Every route returns 401 without a token (settings and communication).
- Password change: wrong current / mismatch / weak / too short / same-as-old / >128 chars all rejected with 4xx; the request does not accept another user's id (uses the token's user).
- Currency: duplicate code (case-insensitive) rejected, cannot delete the active currency, cannot activate an inactive/unknown one.
- Timezone: unknown IANA names are rejected (422); list endpoint returns 597 zones with offsets.
- Passcode expiry bounded 1–30.
- Notifications are scoped to the current user (cross-user ids return 404).
- Settings tabs render: Profile, Preferences, Notifications, Email Templates, Email Logs; Company: Details, Payment Cards, Currency, Security. 1024 px width without horizontal overflow.

## Side effects of the test run (restored)
- `PUT /settings/company` tests changed many values; the pre-test row was snapshotted and restored (verified equal).
- Preferences test poisoned the admin's preferences row (finding 3); restored from the snapshot with a DB script.
- Profile tests altered the admin's first name (restored to `Admin`) and **birthdate (original value was not captured; set to NULL)**. Password was not changed.
- QA currencies and email-template edits were reverted.

## Suggested fix order
1. #1 response model for `/settings/profile` (and never return the hash) — **do first**.
2. #2/#9 permissions on email templates/logs/draft (e.g. `SETTINGS_VIEW/UPDATE`, document view permissions).
3. #3/#4/#5 strict schemas for preferences, company settings and profile (lengths, ranges, enums, email, dates, currency must exist) with lenient response models; repair of existing bad rows is not needed beyond the dev DB.
4. #6/#7/#8 currency/template/id bounds; block deactivating the active currency.
5. #10–#12 (optional): version token on company settings, input `maxLength`.

## Fix log (2026-10-09)
Verified by 83 new backend tests (`backend/tests/test_settings_validation.py`), re-running the audit script (every 5xx is now 422/400, no field leaks), and the live Company Settings form.

- **#1 password-hash leak:** `PUT /settings/profile` now has a response model (`id, username, names, gender, dates` only). Test asserts `hashed_password`, `permissions`, `is_superuser` are absent.
- **#2/#9 email permissions:** logs and templates need `settings:view`, editing templates needs `settings:update`; drafting or sending an email for a document needs that document's view permission (quotation / sales order & invoice / sales return / purchase order / purchase return). Unknown document types are 422, a missing document is 404. The Settings page hides the Email Templates / Email Logs tabs for users without `settings:view`.
- **#3 preferences:** strict schema — theme `light|dark`, `items_per_page` 5–200, valid IANA timezone, real branch name or blank, date-format pattern, 3-letter currency, explicit null rejected. The response schema is lenient, so a legacy NULL row no longer 500s the page (tested).
- **#4 company settings:** names/address/email required and bounded (email uses a simple pattern so the seeded `admin@tijaero.local` still saves — `EmailStr` rejects `.local`), percentages 0–100 and finite, leaves 0–365, fax pattern, real `MM-DD` fiscal start (rejects 02-30), currency must be a configured active currency, logo id range, nulls rejected. Form: required markers and `maxLength` on name/address/email/tax number.
- **#5 profile:** names 1–30, gender ≤ 30, dates must be real `YYYY-MM-DD` (so `"yesterday"` is refused), no future / pre-1900 birthdate; blank optional fields become null; `date_joined` blank = unchanged. Date inputs have min/max.
- **#6 currencies:** code is exactly 3 letters (upper-cased), name ≤100 and symbol ≤10 non-blank (create and update), nulls rejected, ids bounded, the **active currency cannot be deactivated** (nor deleted), duplicate-create races → 1×200 + 7×400 (was 2×409).
- **#7 email templates:** subject ≤255 / body ≤20 000, non-blank, only the known tags (`{document_id} {customer_name} {supplier_name} {title} {name} {company_name}`), balanced braces; ids bounded.
- **#8/#12:** all ids bounded (notifications, currencies, templates, draft), notification `skip` ≤ 1 000 000 and `limit` ≤ 1 000; `/email/send` bodies bounded.
- **#10 concurrency token on company settings:** not added on purpose — each tab saves only its own fields (partial PUT), so two admins on different tabs do not overwrite each other; same-field races are last-write-wins.
- **#11:** `maxLength` added (see above).
- Text such as `<img onerror>` is still accepted as data (names are free text); it renders escaped in the UI.
- Test-run side effects were restored again (company settings equal to the snapshot, admin first name `Admin`, preferences defaults; admin birthdate remains empty).
